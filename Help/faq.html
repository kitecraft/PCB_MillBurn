The exported files

Every layer you enable becomes its own file. A board typically exports as something like: 

MyBoard-F_Cu.nc            top copper, isolation routing
MyBoard-PTH.nc             plated holes
MyBoard-NPTH.nc            non-plated holes
MyBoard-Edge_Cuts.nc       board outline, with tabs
MyBoard-F_Silkscreen.svg   legend, for the laser

The name keeps the layer’s own stem, so the output sorts next to the file it came from, and the extension says which machine wants it: .nc for the mill, .svg for the laser.

Two of the Export window’s tick boxes add a companion beside each program, named so it sorts next to the one it belongs to and so nobody has to wonder which of two files is the one that cuts: 

MyBoard-F_Cu.dryrun.nc     the same path, 5 mm up, spindle off
MyBoard-F_Cu.levelled.nc   the same path, depth following the measured surface

Drill programs also get a MyBoard-PTH.drilling.html, which is a page rather than a program: the bits in order, their hole counts, and when the run stops to change them. See Drilling: which bit, and when it stops.

See Watching a job before it cuts anything and The board is not flat. Job › Write probing routine… writes one more, MyBoard.probe.nc, which is what measures the surface in the first place.

One file per layer is deliberate. A single program containing isolation, three drill sizes and the outline assumes one person watching one long run. Split up, a broken bit costs you the drilling rather than the board — and it is the only arrangement that works at all when the silkscreen goes to a laser while the outline goes to the mill.

Run them in this order: isolate, drill, cut out. The outline goes last because once the board is free of the stock it is no longer held.

Save the project and it remembers all of this. What each layer becomes, which tool cuts it, the depths, the tab count, mirrored, inverted — reopening gives you back the job you set up rather than the defaults. That is the point of saving one: the second setup is the one that quietly differs from the first.

Where is work zero?

The lower-left corner of the board — not of your stock, and not wherever the board happened to sit on the EDA canvas. Every file in one export shares it, and every file says so in its header.

Gerber coordinates come from wherever your board was placed in the schematic tool. PogoTest1, for example, lands at X150 Y−90. Emitting that raw would need you to set work zero at a point you cannot see or measure, so the coordinates are shifted to the board’s own corner instead.

So: jog to the lower-left corner of where the board will be, zero X and Y there, and load any of the files. They all agree.

Watching a job before it cuts anything

Tick Also write a dry run of each program in the Export window and every .nc gets a companion beside it — Board-F_Cu.dryrun.nc next to Board-F_Cu.nc. It traces exactly the same path, held 5 mm above work zero, with the spindle never started. Set work zero as you would for the real job, run the dry one, and watch.

It answers the questions that otherwise cost a board: is work zero where you think it is, does the job fit on the stock, does it reach past a clamp, is the cutter on the side of the line you expected, and how long is this actually going to take. Until this existed the first run of any program was into copper.

The feeds are kept, so the dry run takes as long as the real one. That is deliberate: half the value is finding out that a job you were about to start is a ninety-minute job.

The rewrite is done on the emitted file, not on the toolpath that produced it. Those two agree right up until the emitter has a bug — and only one of them is what the machine will run. Every Z word becomes the safe height, every M3/M4 is removed, an M5 and a lift are put at the top before anything moves sideways, and the result is read back and measured before it is written.

A dry run proves the path, not the machine. It cannot know that your tool is long enough to reach, that the stock is where the fixture thinks, or that a clamp will be in the way at depth. Watch it; do not walk away from it.

A program that selects incremental mode (G91) is refused rather than rewritten: a Z word there is a change, not a position, so substituting a height would send the tool somewhere nobody asked for. Nothing this app emits does that, but files from elsewhere might.

From the command line: millburn export <folder> --dry-run --write, with --dry-run-height <mm> if 5 mm is not the clearance you want.

Dialling a bit in: test cuts

Job → Test cuts… writes a small program that cuts a few lines on a piece of scrap, and an HTML page beside it explaining how to read them. Two tests:

  • Depth and width. One line per depth, getting deeper. For a V-bit this is the important one: measure each line and compare it with the width the app predicted. If they disagree, the tip or the angle in your tool library is wrong — and every isolation job on this machine is computed from those two numbers.
  • Feed rate. One line per feed, all at the same depth. Nothing about the geometry changes; what changes is how clean the edge is, and that is something you can only see. Pick the fastest line that still looks right, not the cleanest one.

Both cut the first line again at the far end of the coupon. Measure both: if they do not match, the stock is tilted or Z moved during the run, and nothing else on the coupon means anything. It costs one line and about four seconds.

Use scrap, hold it down across its whole area, and zero on the copper. The page written beside the program says how much bare copper the test needs, so you can find a piece before you clamp one.

Never level a test cut with your board's height map. A map describes one piece of stock in the position it was clamped in, and a test coupon is a different piece in a different place. If the scrap will not sit flat, the dialog offers a probing routine sized to the coupon itself — probe that, import it, and level the test file against it.

How wide is the gap around each trace?

As wide as you say. Isolate (mm) on a copper layer is the moat cleared either side of every trace and pad, and it defaults to 0.4 mm.

You set a width, not a number of passes. How many laps that takes depends on what your bit cuts at its depth — and for a V-bit that is itself a calculation — so the app does the sum and shows it under the box: 4 passes of 0.127 mm clears 0.450 mm. Change the bit or the depth and the number of passes changes by itself.

Why not just one lap? One lap of a 30° V-bit at 0.05 mm deep clears 0.127 mm. Electrically that is a perfectly good isolation — the nets are separate and the board works. Physically it is a hairline: you cannot see it against the copper, solder wicks across it, and a thumbnail or a bit of swarf can close it. A moat you can see is worth the extra cutting.

It is not free. Four times the moat is roughly four times the cutting time, and on a dense board that is the difference between an hour and four. The export window shows the time bracket for every file before you write anything, so make the trade there. Slightly less than four times, in practice: once a narrow field between two traces is fully cleared, there is nothing left for the next pass to cut.

Zero means one lap, whatever the bit happens to cut — the old behaviour, if you want it. A project saved before this existed keeps exactly the isolation it had.

The starting value for newly imported boards is in Edit → Settings → Milling. Each layer can then be set on its own, which is worth knowing if you isolate the two sides of a board differently.

Why does the isolation depth change the cut width?

Tip width is in millimetres here, and most listings quote it in inches. A typical engraving-bit specification reads Shank Diameter: 1/8 inch, Overall Length: 1-1/2 inch, Tip Width: 0.005 — and that last one is inches too, even though it does not say so. 0.005 in is 0.127 mm.

Typed straight in as 0.005 mm, it describes a bit twenty-five times finer than the one in your hand, and nothing about the result looks wrong: the cut width is computed correctly from the tip, the passes are counted correctly from the cut width, and the first pass is placed half a cut-width clear of the copper. The real cutter, being wider than the app believes, then takes that margin out of the trace instead of out of the gap beside it — so every trace comes out narrower than you drew it, and a thin one can be cut through.

The tool editor says something when a tip looks too fine to be real. It is a notice, not a refusal — fine bits do exist — but it is worth reading.

You can measure it. Cut one straight line at a known depth, measure its width, and work backwards: tip = width − 2 × depth × tan(angle / 2). Do it on stock held down across its whole area, because at this sensitivity a few hundredths of depth error moves the answer.

Because a V-bit is a cone. The deeper it goes, the wider it cuts: 

width = tip + 2 · depth · tan(included angle / 2)

A 30° bit with a 0.1 mm tip at 0.05 mm deep cuts 0.127 mm wide. That is why the app shows you the width rather than letting you type it: the width is a consequence of the depth, not a separate setting.

It also means depth accuracy matters more than it looks. With that bit, 0.01 mm of depth error moves the cut width by about 5 µm — and on a board that is not perfectly flat, the depth varies across the surface whether you asked it to or not.

The included angle is the full angle. Both conventions are in circulation, and reading a 30° bit as a half angle doubles the answer. If your cut comes out roughly twice as wide as predicted, check that first.

What is “through the back”?

How far past the underside of the board the tool goes. It appears only for operations that have to cut all the way through — drilling and the outline — and defaults to 0.3 mm.

Stopping exactly at the nominal board thickness leaves a skin that tears rather than cuts. The board thickness itself is one setting in Project info, because it is one physical fact about the material in the machine; the break-through belongs to each operation.

Isolation has no break-through, because it is not going through anything — it is a scratch a few tens of microns into the copper.

Tabs, and what happens if you use none

Tabs are short uncut bridges that keep the board attached to the surrounding stock while the outline is cut. The default is four, spaced by arc length around the profile rather than by vertex — offset contours bunch their vertices at corners, so spacing by index would put every tab on one corner.

Zero tabs cuts the board completely free. The last few millimetres of the pass then have a loose board next to a spinning cutter, which throws it. The app warns about this in the export confirmation; it does not stop you, because there are fixtures where it is the right answer.

Break the tabs with a knife afterwards and file the nubs flush.

Tabs go on the outermost profile only. A tab holds a piece to the material around it, so the only boundary that needs one is between the job and the stock it sits in.

On a panel that means the frame gets tabs and the boards inside it do not — they are already joined to each other by whatever the designer drew. Adding four more to every one of them leaves a panel that has to be cut apart by hand, which is the opposite of what tabs are for.

Why the file is so much smaller than the board looks

Exported programs are simplified: points that say nothing are dropped, and the fans of tiny segments that a rounded corner arrives as become real G2/G3 arcs. A 66-up panel goes from about 301,000 lines to about 15,000.

This is not about disk space. A controller slows down for every block it cannot see past, so a contour delivered as thousands of one-micron moves never reaches the feed you programmed — the machine crawls through geometry it could have taken at speed. Fewer, longer moves is the single biggest thing that makes a job finish sooner.

Nothing moves more than 2 µm from where it was asked to be, and that bound covers both steps together rather than each of them separately. For scale, that is under two percent of a 0.127 mm isolation cut, and below what the machines this targets can repeat anyway.

The board is not flat: probing and height mapping

Isolation cuts 0.05 mm deep. An ordinary piece of copper-clad FR4, clamped at its corners, is 0.1–0.2 mm out of flat. Those two numbers are the single most common reason PCB milling disappoints people: the same program skates over the copper at one end of the board and ploughs through into the substrate at the other, and there is nothing wrong with the file.

The fix is to measure the surface and follow it. Three steps, and you only do the first two once per piece of stock.

  1. Job › Write probing routine… Put a probe on the tool and a clip on the copper, set work zero exactly as you would for the real job, and run the file. It touches off a grid over the board — ten millimetres apart by default, about four seconds a touch.
  2. Save your sender's log, then Job › Import height map… The status bar tells you how far out of flat the stock turned out to be, which is worth knowing on its own. If the file is not a probe log, a dialog says so and says why — an import never fails quietly, because a failed import changes nothing on screen and would otherwise look exactly like a successful one.
  3. Export with Level to the imported height map ticked. Each program gets a .levelled.nc beside it whose depth follows the surface.

Your sender’s preview of the probing file may look alarming, and be wrong. Plenty of G-code viewers have no G38.2 in their vocabulary — it is “probe toward the work”, not a cutting move — and simply skip the line. The preview then shows no Z movement at all, or draws the tool going down at the first point and dragging across the whole board at depth.

The file is right; the picture is not. Every touch in it is three lines: a move to the point at Z1.000, a probe down, and a retract back to Z1.000. You can read them in the file, and the header says so as well, because this is the moment it matters. Nothing in a probing routine cuts — there is no spindle command in it at all.

Work zero must be in exactly the same place when you cut as when you probed. If it moved, the levelled file is worse than the unlevelled one — it is now confidently applying the wrong correction. Probe, then cut, without re-zeroing in between.

A height map belongs to the piece of stock on the table, not to the design. It is deliberately not saved into your project: unclamp the board and the map stops being true.

What it reads

Any log with the numbers in it. GRBL probe reports — [PRB:12.000,8.000,-24.512:1] — are found in among whatever else your sender wrote to the console, and so is a plain file of three numbers a line separated by commas, tabs, semicolons or spaces. A header row is fine. A probe that never touched anything (a trailing :0) is thrown away rather than believed, because the position it reports is where the machine gave up.

GRBL reports those positions in machine coordinates, tens of millimetres from zero in all three axes, while the probing routine was written in work coordinates like every other file here. Both halves of that are handled and both are reported.

  • Height is re-datumed to the board's own corner, which sits on the surface, so the height there is zero by definition.
  • Position is recovered from the log itself. Most senders echo the commands they send, so the file contains the G0 X… Y… moves in work coordinates alongside the replies; the difference between the two sets is your work offset, and every point is moved by it.

If your log holds only the [PRB:] replies and none of the commands, nothing in it records where work zero was, and the import says so rather than guessing. Log the commands as well as the replies — most senders do by default.

What it refuses, and why it tells you

The reader is forgiving on purpose, and forgiveness has a cost: hand it something that is not a log at all and it would once have found nothing and said nothing. The import is checked, and a file that fails is refused with the reason, out loud.

  • Nothing in it is probe data. No [PRB:] report and no line of three numbers. This is what you get from a G-code program, a Gerber, or a page of notes.
  • Mostly unreadable. A header row or a stray comment is normal; a file where more lines failed than parsed is a file that happens to contain a few numbers.
  • Every probe failed. All the reports carry :0. Nothing was measured — check the clip is on the copper and the probe on the tool.
  • The probe never moved. Every point at the same X and Y. That is a repeatability test, not a surface.
  • Z values spanning more than 10 mm. No board is that far out of flat. It is the wrong file, or probes that ran to the end of their travel.

A refused import leaves whatever map you had before exactly where it was, and says so — otherwise Forget height map staying enabled would read as the new file having loaded.

This has only ever been tested against GRBL. The shape of a probing log is a property of your controller and your sender, not of this app, and no amount of care here can anticipate a format nobody has seen. grblHAL and FluidNC answer in the same dialect and are very likely fine; LinuxCNC's (PROBEOPEN file) writes a plain table of numbers which should read as a triples file, untested; Smoothieware, Mach3 and Mach4 depend entirely on the macro that wrote the log.

If yours will not import, that is worth reporting and it is almost certainly not your fault. Send the log itself, whole and unedited — the ok lines and the echoed commands are not noise, they are where the work offset is read from — plus your controller, its firmware version, and your sender. We will do our best to read it.

On a GRBL-family board, type $I in your sender's console before you start the probing run. Its reply names the firmware and lands in the same log, which answers the first question any report raises. It is deliberately not in the probing file: GRBL refuses $ commands while a program is running, and a diagnostic that can abort your job is a bad trade. The probing file's header says to do it.

A map is for one side of one board, as it is clamped right now

A map measures one face of the stock, as it was clamped at the time. The export asks which face — the board was top-up / flipped when you probed it — because nothing in the log says, and only you know. Programs cut on that side are levelled; programs cut on the other side are refused, by name, with the reason.

Top-up is the usual answer, and it covers more than the top copper: drilling and the board outline are cut with the board that way up too, so they are levelled alongside it. The only file left out is the mirrored one. The window lists them both ways round before you write anything.

Applied across the flip the correction would land on the wrong point — the coordinates have been mirrored — of the wrong surface. Wrong twice, and confidently. No arithmetic rescues it, because the board is re-clamped when you turn it over.

So to level both sides you probe twice. Cut the top, flip and re-register, probe again, import the new map, and export the bottom with flipped chosen. Or level that one file on its own: millburn level Board-B_Cu.nc --map second-probe.log. On the command line the export takes --level-side top|bottom, and defaults to top.

It is the same reason a map is not saved into your project. It describes the piece of stock on the table in the position it is in, and almost nothing you do to a board leaves that true.

Hold the board down everywhere, not just at the edges

This is the one that catches people, and it is worth understanding rather than just obeying.

A probe and a cutter press on the board with completely different force. The usual PCB probe is a continuity touch — a clip on the bit, the copper as the other contact — and it triggers the instant the circuit closes, at essentially no force at all. A cutter is not being gentle: it is pushing down into the material hard enough to remove it.

So if the board is only taped at the edges, the map you measured and the board you cut are two different shapes. The probe floats over an unsupported middle and records it where it lies; the cutter arrives at the same spot, presses, and the board moves away from it. The correction is then applied confidently to a surface that is no longer there — and because the file looks levelled, the result is a board that is wrong for a reason nothing shows you.

Stick the whole underside down. Double-sided tape across the full area, or a vacuum bed. Not tape at the corners, not clamps at two edges. The point of a height map is to measure a shape that will still be that shape when the cutter gets there, and only a board that cannot move satisfies that.

The app says something when the numbers look like this has happened: a lot of bow across a small piece is much more often a hold-down that is not holding than stock that is genuinely that bad, because sag grows with the square of the unsupported span. It is a note, not a refusal — you might have a genuinely warped offcut — but it is worth reading before you cut.

What it does between the touches

A thin-plate spline — the shape a thin sheet of metal would take if it were forced through every measured point and otherwise left alone. Not bilinear interpolation on a grid, which leaves a crease along every grid line, and a crease in the depth of a cut is a visible line in the copper.

Cutting moves are broken into 1 mm steps so they follow the surface rather than chording across it; moves held in the air are left long. Cutting arcs become straight segments, because an arc whose depth changes along its length is not something G2 can express.

If the measurements cannot support a surface, it says so and does less rather than inventing one: probe points all in a line give a tilted plane, two points give a plane, one gives a flat offset.

Outside the probed area it holds the edge value rather than extrapolating. A spline has no opinion about ground it has not been shown, and its tilt would run off into space — on a board 0.1 mm out of flat, carrying that trend a few centimetres past the last touch produces a correction of millimetres, which drives the cutter through the board. If the job runs more than 3 mm outside what you probed, levelling is refused outright and tells you to probe a bigger area.

From the command line: millburn probe <folder>, then millburn export <folder> --level <log> --write. There is also millburn level <program.nc> --map <log>, which will level any G-code, not only ours.

A trace did not get isolated

If two traces are closer together than the tool is wide, there is no path that fits between them, so none is produced. The app counts these and lists them under CHECK.

This is worth understanding because of how it fails: a gap the tool cannot enter leaves the copper connected and draws nothing. The picture looks perfect and the board is shorted. That is exactly why it is reported rather than left for you to spot.

The fixes, in order of how much they cost you:

  • Cut shallower — a V-bit gets narrower as it comes up. 0.05 mm → 0.03 mm takes a 30° 0.1 mm bit from 0.127 mm to 0.116 mm.
  • Use a sharper bit (a smaller included angle, or a smaller tip).
  • Widen the clearances in your design.

Lining up the two sides of a double-sided board

This is the hard problem in home PCB milling, and it has a good answer. The principle is worth stating first, because everything else follows from it:

Drill everything in the first setup, before the board ever moves. All holes, all the way through, while the stock is still located. After that the holes themselves are the registration — you are no longer trying to align two sides, only to put the board back where it was.

What to add to your design

Two NPTH (non-plated) holes, 3.0 mm, placed in the waste area outside Edge_Cuts. In KiCad these are just mounting holes with no pad. They come through in your normal drill file, so nothing special is needed on either side — no custom layer, no export tricks.

Where to put them matters, and there are exactly two rules:

RuleWhy
Mirror-symmetric about the board’s vertical centreline — same distance left and right, same Y. That is the axis the app mirrors the bottom side about, so the board only drops back onto the same two pins if the holes straddle it symmetrically.
Both off the horizontal centreline — put them near one edge, not halfway up. Otherwise the board also fits rotated 180°, which looks identical and is not. Off-centre holes give you exactly two valid placements: top-side and flipped.

As far apart as the stock allows. A long baseline turns any given positional error into a smaller angular one.

The pin-plate method — recommended

The tightest of the practical fixtures, and the cheapest to make.

  1. Fix a piece of scrap MDF or acrylic to the spoilboard. This becomes the plate, and it stays put for the whole job.
  2. Tape or clamp your copper stock on top of it. Set work zero at the board’s lower-left corner.
  3. Run *.drill.nc and let it go through the stock and into the plate in one operation. The stock holes and the plate holes are now at the same coordinates by construction — nothing was measured, so nothing can be measured wrong.
  4. Press two dowel pins into the plate holes. 3 mm ground dowels are a few pence each.
  5. Drop the stock back on the pins and run the top-side work: *.iso.nc for F_Cu.
  6. Lift the board, flip it left-to-right about its vertical centreline, drop it back on the same pins. Not top-to-bottom, and not diagonally.
  7. Re-zero on the lower-left corner — which is now the corner that used to be on the right — and run *.iso.nc for B_Cu. That file is already mirrored for you.
  8. Cut the outline last, while the board is still pinned.

With 3 mm dowels in holes drilled by the same program, expect 20–50 µm. That is good enough for 0.2 mm traces.

Deburr before you flip. Drilling through leaves a burr on the underside, and that face becomes the mating face after the flip. A burr lifts one corner of the board by more than your whole registration budget. A light pass with a deburring blade or fine abrasive is enough.

What the app does about the flip

Every layer that produces a file has a Mirrored checkbox. It is ticked by default for bottom-side layers and clear for top-side ones, which is right for the usual workflow — but it is a checkbox rather than a rule, because which way round you want a layer is a question about your process, not a fact about the file.

The two cases where the default is wrong:

  • You are burning a mask onto a transparency that will be laid face-down on the board. That wants the opposite handedness from engraving the same layer directly.
  • You laid out a single-sided board on the bottom copper and are cutting it from the top of the stock, without flipping anything.

The setting applies to SVG as well as G-code, about the same axis, so a layer sent to both machines comes out the same way round in both.

The mirror is about the board’s own vertical centreline, so the output still occupies exactly the same box — work zero is still the board’s lower-left corner in both setups. That is the corner you can still see and touch off on after the board has been turned over. For SVG, the drawing stays on the shared page, so mirrored and unmirrored layers still overlay when they are imported.

A mirrored file says so in its header, in the export confirmation, and in CHECK — a reminder that the stock has to be turned and re-registered. And if you tick or untick the box against the default for that layer’s side, the export confirmation says that too, in both directions. Both overrides are legitimate; both are invisible once the file is written.

Flip left-to-right, about the vertical centreline. Flipping the other way produces a board that is wrong in a way which is completely invisible until you try to fit a part to it. If you are unsure, mark one corner of the stock with a pen before the first cut.

Other methods, and what they cost

MethodTypical accuracyNotes
Pin plate, holes drilled in the first setup 20–50 µm Recommended. Needs two holes in the waste area and two dowel pins.
Corner stop, as-supplied stock ±0.15–0.25 mm Fine for drilling and cutting out; not enough for double-sided isolation. Sheared copper-clad is not square and its edges are not straight.
Corner stop, after milling the two datum edges true ±0.05 mm One extra pass and a few millimetres of stock. Needs a second, mirrored stop for the flipped side, since flipping swaps which physical edge meets which stop.
Fiducials, measured by eye 50–100 µm Free. Adequate for 0.4 mm-plus traces.
Fiducials, USB microscope with a crosshair 20–30 µm Best accuracy per pound spent by a wide margin. A cheap scope taped to the spindle.
Fiducials, touch probe into the registration holes 10–25 µm Four touches around each bore, then a circle fit. Fully numeric, nothing eyeballed.

not built yet Fixture generators (corner stop, dowel plate, nest pocket), automatic fiducial placement, and fitting a measured transform back into the output are all planned. Today the mirror is handled for you and the registration is yours — which the pin-plate recipe above covers without any of that, because it never measures anything. Probing itself is built, for surfaces rather than for alignment: see The board is not flat.

Why the app will never do this over a cable. PCB_MillBurn writes files; it does not drive machines. When measurement does arrive it will be numbers in, G-code out: you jog to a mark in whatever sender you already use, read the DRO, and type the numbers in. That works with every controller and every sender that has ever existed, and there is no firmware compatibility to go stale.

Can I panelise?

A panel you made in your EDA tool is cut correctly. Every closed profile in Edge_Cuts is milled — a 66-up panel gives all 66 boards plus the frame — and the pieces inside are cut before the frame around them, because taking the frame out first leaves everything still attached to it loose while the cutter is still working.

Making the panel is your EDA tool's job, and it is not going to be ours. For KiCad the answer is KiKit, which lays out the array, adds mouse-bites or V-scoring, handles tooling holes and fiducials, and knows about your netlist and your design rules. Altium and Eagle have their own. Whatever they produce, this app cuts.

Why not here. Panelising properly means understanding the design, not just the geometry — which copies share a net, where a mouse-bite may cross a trace, what the clearances are. By the time a board reaches this app it is a set of Gerbers: shapes on layers, with the design gone. A CAM-side array could copy the shapes, and it could not tell you it had put a perforation through a track. A tool that panelises badly is worse than one that does not pretend to.

The one cost of panelising upstream is that the Gerber set you get back is no longer your board: layer roles are still read correctly and the cutting is right, but Refresh from source can no longer tell you what changed in the design, because everything changed. Keep the single-board project alongside the panel one if that matters to you.

Two things worth knowing before you decide to panelise at all:

  • Isolation milling a panel takes N times as long, and isolation is where bits break. One snapped V-bit part way through costs you six boards instead of one. For most home work, running the same job six times is genuinely the lower-risk option.
  • Panels amplify flatness problems. Across 30 mm you can usually ignore how flat the stock is; across 200 mm you cannot, so probe the panel and level the job — see The board is not flat.

Milling the soldermask off the pads

Set a paste or soldermask layer to G-code and you get mask relief: the cured soldermask cleared off each pad so it can be soldered.

Either layer works, and which you want depends on what you are soldering. The paste apertures are where solder paste goes: the pads of surface-mount parts. The soldermask openings are everywhere the mask is not meant to be at all, which is a superset — through-hole pads, vias and test points have mask openings and no paste.

Each opening is cleared with rings working inwards from its edge, and each pad is finished before the tool moves to the next. Openings smaller than the tool cuts are counted and reported: they will keep their mask, and nothing about the picture would tell you.

This is the operation that board flatness ruins. Cured mask is about 0.02–0.04 mm. The whole depth of this cut is smaller than the flatness of an ordinary piece of copper-clad over even a small board — so the same program leaves mask on one pad and cuts into the copper of another, and neither shows up until the board is under a light.

Use a height map for this one. Of everything the app does, mask relief is the operation that most needs it: probe the stock, import the log, and tick Level to the imported height map when you export. See The board is not flat.

The depth defaults to 0.035 mm here rather than the 0.05 mm that isolation uses, because 0.05 mm goes clean through the mask into the copper. If you type a depth of your own it is kept, whatever you switch the layer to afterwards.

Etching: burning the negative

Two opposite jobs use the same shapes, so each exported SVG has an Inverted option.

JobInvertedWhat the laser burns
Clear soldermask off the pads off The shapes themselves — the openings.
Etch a painted board in acid on Everything inside the board edge except the copper, so the resist is cleared wherever the acid should reach.

Inverting needs the board edge, and puts it in for you: the complement of a shape is unbounded until something bounds it, and what bounds it here is the material. The Edge_Cuts outline is used when there is one, so a board that is not a rectangle comes out the right shape; without an outline it falls back to the extents, and says so.

It applies to drawings only. A toolpath has nothing to be the complement of, so the setting is ignored for G-code rather than producing a program that mills the whole board away.

Drilling: which bit, and when it stops

Drilling is the only operation with tool changes in it, so it is the only one where the program alone does not tell you what to do. A board with holes in four sizes is four runs with three stops between them, and the file says so only in comments you would have to go looking for.

So every drill program gets a page beside it — MyBoard-PTH.drilling.html next to MyBoard-PTH.nc — listing the bits in the order they go in, how many holes each one makes, roughly how long that takes, and which line of the program it starts at. Open it in a browser and work down it.

It is one self-contained file with no links out, so it opens on a workshop machine that has never been online. Untick Drilling guide on the layer if you do not want it.

The program stops on its own between bits — spindle off, tool lifted clear — and waits. Change the bit and resume in your sender. X and Y have not moved and do not need re-setting.

Re-zero Z after every bit change. A new bit sits at a different height in the collet, and the depths in the program are measured from the surface of the board, not from the spindle. This is the one part of a tool change that cannot be done for you, and getting it wrong either drills nothing or drills through the table.

Biggest bit first. That is the opposite of what feels natural, and it is deliberate: a small drill wanders when it starts on a surface a larger one has already broken, so the usual reason to go small-to-large does not apply. It also means the delicate bits spend the least time in the spindle.

If your drill file lists the same position twice for the same bit — real ones do — it is drilled once, and the page says how many were repeated. Drilling a hole that already exists cuts nothing and is how drills get grabbed and snapped.

Holes of different sizes, and drill files that are Gerbers

Slotted and oval holes are not made

A slot — an oval pad, or any routed hole — is not a plunge, and nothing here routes one yet. They are read, they are drawn on screen, and they are left out of the drilling program, which says so: the export lists them separately and warns that the parts needing them will not fit. Cut them yourself, or leave that connector off.

A drill cannot make one anyway. A twist drill cuts on its point and will not travel sideways, so a slot is an end mill job — plunge and traverse with a cutter no wider than the slot. That is a different tool class and a different motion from everything else in a drilling program, which is why it is not simply folded in. It is the next thing being built, and it will land as a separate slot program beside the drill file.

Worth knowing because the picture gives you no clue. The slots appear on the board exactly as your EDA tool drew them, so there is nothing to notice until a part will not go in. Every KiCad board with a slotted pad has some — an Arduino Mega has seven.

Different sizes in one file

A drill layer becomes one program containing every hole, grouped by size, largest first. Each group is a tool change, marked in the file, so you run it, stop at the change, swap the bit and carry on. Sizes are not split into separate files: they share one work zero and one setup, and splitting them would mean re-registering between bits for nothing.

Largest first because a big bit wanders less when it starts on undisturbed material than when it meets a smaller hole already there.

“My drill files came out as .gbr”

That is KiCad’s Generate Drill Files with the Gerber X2 option rather than Excellon. It works here: the holes are read straight out of the file, with the exact aperture diameters rather than measurements taken back off the drawing.

That export also writes a drill map (*_map.gbr) — a chart of symbols and text showing an operator where the holes go. It appears in the layer list as Drill map, switched off, and cannot be exported: it is documentation, not holes. Leave it in the folder; nothing will be cut from it.

The same goes for fabrication, assembly and array drawings, which show as Documentation. All of them are recognised from the file’s own declaration rather than from its name — which matters, because a drill map is usually called something like Board-PTH-drl_map.gbr and a name-based guess reads that as plated holes.

The SVGs: masks, openings, and alignment

Why does the soldermask SVG show holes rather than mask?

Because that is what the file contains. A soldermask layer is usually negative: the shapes drawn in it are the places where there is no mask — the pad openings.

The app reports this rather than silently inverting it, because inverting requires inventing an outer boundary, and any boundary it invented would be a guess. What CAM actually wants is the openings, which is what you get. The export confirmation says “the shapes are the openings, not the material” for exactly this reason.

Do the SVGs line up with each other?

Yes. Every SVG in one export shares one page, sized to the whole board rather than to each layer’s own extents. Import them into your laser software and they overlay correctly with no adjustment.

This is worth being deliberate about: cropping each layer to its own bounding box is the mistake that puts a second burn out of register by the difference between two crops — a small, plausible error that only shows up on the finished board.

Each file is also written as a single layer. Some laser software creates one of its own cut layers per imported object, which turns a board into several hundred of them.

Looking at a G-code file

File › Open G-code…, or drag a .nc onto the window, or pass one on the command line. It draws — cutting moves, travel and long rapids, each its own layer you can turn on and off — with the cut and travel distances, the plunge count and the line count along the bottom.

It will draw any G-code, not only ours. The viewer has always worked by parsing the emitted text rather than the toolpaths behind it, so a program from another CAM tool, or one you edited by hand, opens exactly the same way. Anything the parser could not make sense of is listed, so a picture with something missing from it says why.

It is the way to look at the files that are not the job itself: the .dryrun.nc, the .levelled.nc, and the .probe.nc. Open a program over the board it came from and it lands on the copper; open one with no board and it stands on its own. File › Close G-code puts the board back.

A dry run is all travel — that is what makes it a dry run — so it draws entirely in the travel colour with nothing in the cutting one. A program opened on its own turns every layer on for that reason. If it still looks empty, check the travel colour is not something invisible against your theme: click the swatch beside the layer, or Edit › Reset layer colours.

Settings: safe height, and the rest of the machine

Edit › Settings… holds the numbers that describe your machine rather than your board, so they stay put when you open a different project.

Safe height is the one to check first. Every travel move in every program this app writes crosses the board at exactly that height — and it defaults to 2 mm, which clears a bare board and very little else. If anything stands proud of your stock — clamps, hold-downs, tape, a probe clip — raise it, or the first traverse hits it at rapid.

The rest, briefly:

  • Approach height — where a rapid descent stops and the plunge feed takes over. Lower is quicker and leaves less room for a surface higher than you expected. It has to stay below the safe height.
  • Rapid rate — used for the time estimates, and for a dry run with the programmed feeds turned off. It is never written into a file; G0 carries no feed word.
  • Coordinate decimals — three is one micron, past what these machines repeat to.
  • Canned drilling cycles — off, and leave them off for GRBL. It ignores what it cannot parse, so a drill file would travel the whole pattern without drilling anything and without complaining. LinuxCNC and Mach3 do support them.
  • Dry run — how high it is held, and whether it keeps your feeds so the run takes as long as the real one.
  • Probing — grid spacing, feed, search depth, edge margin, and the most touches to ask for. Roughly four seconds a touch, so the last one is a time budget.
  • Levelling — how finely a cut is broken up to follow the surface, how far outside the probed area a job may stray before it is refused, and how much to relax the fit against probe noise.

Save is refused while anything contradicts itself — an approach height above the safe height, or a dry run held lower than the job's own travel. Those are not preferences, and silently correcting one would leave you believing the machine is set up one way while it is set up another. Restore defaults puts every number back.

My machine needs its own lines at the start

Edit › Start and end G-code… Whatever you put there goes into every program this app writes: a homing cycle, a work offset, a vacuum relay, a spindle dwell, a coolant line. Without it, anyone whose machine wants something ours does not emit is editing every file by hand after every export.

The two blocks land in specific places, and the placement is a safety decision rather than a formatting one.

  • The start block runs before the program sets its own modes. The next thing in the file is always G21 G90 G94 and G17 — millimetres, absolute, XY plane — so whatever state you leave the machine in, the job puts it back before cutting anything. That makes the worst mistake impossible rather than merely warned about: a header that quietly switches to inches or to incremental would otherwise change what every coordinate in the file means, with nothing about the file looking wrong.
  • The end block runs after the spindle stops and before M30, because a controller stops reading at the program end.

Your lines are marked in the output — ( Your start G-code ) — so anyone reading the file can tell at a glance which lines came from your machine profile and which the app wrote.

What it will not let you save

The editor checks as you type. Two things are refused outright, because both produce a file that looks perfectly fine and does not do what it says:

  • A comment that does not close, or a bracket inside one. A G-code comment runs to the first closing bracket, so ( oops (nested) ) ends early and the rest of the line is read as code. LinuxCNC refuses the file outright.
  • M30 or M2. That ends the program where it stands. In a start block, the job never runs at all.

Everything else is advice and you can save it anyway — it is your G-code for your machine. You will be told if you use G92 (it shifts every coordinate after it and the file gives no sign), if you move in X or Y before the program has lifted the tool, or if you set a mode the program is about to set again for itself.

Saved against the machine, not the board, because that is what it describes. A project can carry its own instead, and then keeps it — opened a year later or on another machine, it still has the lines it was cut with.

From the command line: millburn export <folder> --start-gcode <file or text> --end-gcode <…>.

The board pane: what is drawn, and what gets cut

The board pane is the column down the left of the window — the board's own facts at the top, then every layer and what it becomes, then anything worth checking at the bottom.

Each layer gets one row, and the row carries three separate things. They are separate because they answer different questions, and every attempt to fold them into one control ends up answering the wrong one.

  • The checkbox draws the artwork — the copper, the mask, the legend, as the Gerber describes it.
  • The zig-zag beside it draws the toolpath — the program that layer becomes, parsed back out of the emitted G-code after a Preview. A layer that makes no program shows a dash instead.
  • The pill on the right says what it becomes — G-code, SVG, or nothing at all. It is on the collapsed row on purpose: which layers are being exported is the thing you most want to know at a glance, and it used to take opening every one of them to find out.

The artwork and the toolpath are two toggles rather than one because the artwork hides the cuts. A trace is a filled shape and its isolation path runs around the outside of it; with the copper drawn, the line you are trying to look at is a hair against a solid colour. Turning the copper off and its path on is the gesture that makes a toolpath readable, and it needs both halves.

Right-click any layer for Show only this toolpath and Export only this layer…. The second opens the usual export window with just that one file in it — it changes nothing about your settings, so there is nothing to put back afterwards.

And Job → Reset layers to defaults puts every layer back to what it would have been on a fresh import: what it becomes, its tool, depth, passes, tabs and the rest. Board thickness and colours are left alone, because those describe your stock and your eyes rather than the design. It asks first, and it cannot be undone.

Why the list is in that order

Grouped by which part of the board a layer belongs to: top side first, then any inner layers, then the bottom side, then holes and outline, which belong to neither side. Inside each group the copper comes first, because the copper is what gets cut.

It is deliberately not the order the layers are painted in. Paint order is back-to-front, which is right for the renderer and wrong for reading: it opens with the bottom silkscreen, sets the two soldermasks four rows apart with nothing but their labels to tell them apart, and buries the side you are working on in the middle. Each group heading also says how many of its layers are being exported, so a fully collapsed drawer still tells you which parts of the board the job covers.

A mirrored layer’s toolpath

A bottom-side program is written mirrored, because you turn the stock over before you cut it. Its coordinates describe the flipped board, not the one on screen — so the drawing flips them back, and the path is shown where it will actually land on this board, sitting on the copper it isolates. It is still the emitted file being drawn; only the frame it is drawn in has been chosen to match the picture. The warning about which way to flip the stock is unaffected, and so is the file.

Toolpath moves

Under the list, after a Preview: Cutting moves, Travel moves, Long rapids, RAPID AT DEPTH if there is one, and the Substrate. These are not layers — no file makes one and none can be exported — so they are a filter across the whole drawing rather than rows pretending to be files. A path is drawn when its layer’s zig-zag is on and its kind of move is ticked here.

Click the coloured dot on any of them to change its colour, the same way a layer swatch works.

I cannot see a layer

Click the colour swatch next to any layer and pick something you can actually see. Colours are saved globally, not in the project: which colours read well is a fact about your eyes and your monitor, not about the board, so they follow you between projects rather than travelling inside one. Edit → Reset layer colours puts everything back, and Use default in the picker resets just the one.

This includes the things the app draws itself rather than reading from a file. They are not in the layer list — they are the Toolpath moves row of chips underneath it: the Substrate, and, after a Preview, Cutting moves, Travel moves, Long rapids and RAPID AT DEPTH. Click the coloured dot on a chip to change it. Those are often the ones that most need changing. The backplot palette deliberately picks hues the board does not use, so a program is never invisible against the copper it was made from — but which hues those are depends on which layers you have showing.

The checkbox beside each layer controls only whether its artwork is drawn. It has nothing to do with whether it is exported — that is the dropdown, and the pill on the right of the row says what the answer currently is. Keeping them separate is deliberate: you routinely want the soldermask on screen to check a pad against while cutting only the copper.
